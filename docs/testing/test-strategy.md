# Test strategy

## Levels

| Level                           | Tool                                 | Location                                             | What it proves                                                                                                                                                                                                                         |
| ------------------------------- | ------------------------------------ | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit (xUnit style)              | Jest                                 | `tests/unit/`                                        | Business rules in isolation, using in-memory repository fakes: auth, access policies, validation, duplicate prevention, percentage calculation, rate limiting.                                                                         |
| Integration / API               | Jest + Supertest + in-memory MongoDB | `tests/integration/`                                 | The real app (container, routes, Mongo repositories, indexes) on seeded data: status codes, payloads, RBAC, data isolation, concurrency, query plans.                                                                                  |
| API contract / regression       | Postman collection run by Newman     | `postman/` (generated by `scripts/build-postman.js`) | A black-box check of the running server over HTTP: 28 requests, with status, body and response-time (< 1000 ms) assertions.                                                                                                            |
| Manual exploratory / acceptance | Chrome                               | —                                                    | The UI flows were walked through on 2026-11-14: faculty marking, the locked view after saving, the at-risk student dashboard, and the admin overview with drill-down. Screenshots are still to be saved to `docs/evidence/` (Phase 5). |

**TDD** was used for authentication, role checks, duplicate prevention, percentage calculation and
the HTTP routes. Each has a `test:` commit before the `feat:` commit, and the red and green outputs
are saved in `docs/evidence/tdd/`.

**CI** (`.github/workflows/ci.yml`) runs lint, a format check, Jest with coverage, server start and
Newman on every pull request and every push to `main`. Merges to `main` require the `build-test`
check to pass (branch protection).

## Agile Testing Quadrants mapped to tests in this repo

| Quadrant                                                                          | Purpose                     | Tests here                                                                                                                                                                                                                                                                      |
| --------------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Q1** Technology-facing, supports the team (unit/component)                      | Guide the code              | `tests/unit/authService.test.js`, `accessPolicy.test.js`, `attendanceValidator.test.js`, `attendanceRecorder.test.js`, `attendanceCalculator.test.js`, `loginRateLimit.test.js`                                                                                                 |
| **Q2** Business-facing, supports the team (functional / story tests)              | Confirm acceptance criteria | `tests/integration/auth.test.js`, `courses.test.js`, `markAttendance.test.js`, `analytics.test.js`, `seed.test.js`; the Postman collection, whose request names follow the acceptance criteria                                                                                  |
| **Q3** Business-facing, critiques the product (exploratory, UAT, demo)            | Find what the specs missed  | Manual walkthroughs in Chrome on 2026-11-14 (see the PR #5 and PR #8 descriptions). A formal UAT with the Product Owner has not happened yet (GAPS).                                                                                                                            |
| **Q4** Technology-facing, critiques the product (performance, security, "-ility") | Non-functional quality      | `tests/integration/hardening.test.js`: explain plans prove index use (no COLLSCAN), safe 400/404/413/500 errors, security headers, login rate limiting. `tests/integration/duplicateIndex.test.js`: a concurrency race. Newman checks response time < 1000 ms on every request. |
