# SOLID in the Student Attendance Tracker

Each principle is mapped to real files in this repository, with the test that relies on it.

| Principle                     | Where                                                                                                                                                                                        | How it shows                                                                                                                                                                                                                               | Evidence                                                                                                                                                          |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **S** — Single Responsibility | `src/services/AuthService.js`, `src/services/AttendanceValidator.js`, `src/services/AttendanceRecorder.js`, `src/services/AttendanceCalculator.js`, `src/services/AttendanceQueryService.js` | Authentication, request validation, recording (with duplicate prevention), percentage maths and read-side queries are separate classes. Controllers (`src/controllers/*`) only translate HTTP to service calls.                            | Each service has its own unit test file in `tests/unit/`.                                                                                                         |
| **O** — Open/Closed           | `src/config/attendanceRules.js` → `AttendanceCalculator`                                                                                                                                     | The threshold, status weights, alert levels and rounding precision live in config. The calculator reads them and never names a level.                                                                                                      | `tests/unit/attendanceCalculator.test.js` › "Open/Closed: behaviour comes from the rules object" (stricter threshold; late counted as half), with no code change. |
| **L** — Liskov Substitution   | `src/policies/AccessPolicy.js` (`AccessPolicy` → `AdminPolicy`, `FacultyPolicy`, `StudentPolicy`)                                                                                            | Every role policy has the same four methods; callers use `policyFor(user).canX(...)` and never branch on the role. The base class denies everything, so a subclass only widens access deliberately.                                        | `tests/unit/accessPolicy.test.js` › "every policy exposes the same interface (Liskov substitution)".                                                              |
| **I** — Interface Segregation | `AttendanceRecorder` (faculty write side: `markAttendance`) vs `AttendanceQueryService` (read side: `studentSummary`, `studentHistory`, `courseSummary`, `adminOverview`)                    | The student-facing controller (`src/controllers/reportController.js`) depends only on the query service and cannot reach marking methods; the faculty marking controller depends on the recorder.                                          | Routes in `src/routes/index.js`; analytics and marking are tested separately.                                                                                     |
| **D** — Dependency Inversion  | `src/repositories/contracts.js`, `src/repositories/mongo/*`, `src/repositories/memory/index.js`, `src/container.js`                                                                          | Services receive repository objects through their constructors and depend only on the documented contract. `src/container.js` (composition root) is the only file that picks the Mongo implementations. Unit tests inject in-memory fakes. | `tests/unit/attendanceRecorder.test.js` uses `InMemoryAttendanceRepository`; `tests/integration/duplicateIndex.test.js` runs the same service against MongoDB.    |

## A known difference between the fake and the real repository

The in-memory `insertMany` checks the whole batch before writing anything. MongoDB's
`insertMany` (ordered, with no transaction) can leave the earlier rows written if a later row
fails. The code reviewer pointed this out on PR #4, and it is tracked as risk R2 in
`docs/risks.md`.
